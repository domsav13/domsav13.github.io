MAE Senior Capstone

Created on May 10, 2025

2025

For my capstone project, my responsibilities included creating a software and data architecture for our spotlight controls, working with IMUs as a feedback sensor, implementing interprocess communications in the electronics, designing user interfaces, and supporting assembly and manufacturing.

Scope and Requirements

For this project (funded by University Research Foundation), a maritime spotlight that will track and target buoys or other in-water targets to assist in “man overboard” searches and illuminate hazards will be designed, built, and tested. While some spotlights are effective with manual operations, the goal of this prototype is to implement an automatic system in which the light orients itself for stability and to sweep a vessel’s navigational history to point to objects of interest. Building on a previous prototype, research was conducted in areas such as water resistance, power management, motor selection, and control systems to create a more compact, reliable, and user-friendly product.

Due to the sponsor’s expertise and guidance, the following functional requirements were provided during preliminary conversations:

  • The spotlight must provide location data without resetting to a specific position
  • The sensors must provide information for self-stabilization every 0.1 seconds
  • The IMU must provide Euler orientation data that is accurate to 5 degrees
  • All electronics must utilize a shared memory with respective read/write permissions to data
  • All power must be provided by a 12-24 V source
  • The power source must supply 91.2 W of power (calculated) for all electronics
  • The light will be able to pan +360 and -360 degrees and tilt +90 and -45 degrees
  • The motors must be able to accelerate from 60 degrees per second in one direction to 60 degrees per second in the other direction within 0.2 seconds
  • The mechanical design must prevent backdriving in the tilting motion of the light
  • The motors will point the light to $\pm$ 0.2 degrees of accuracy via absolute encoders
  • The pan and tilt motor commands must be able to occur simultaneously
  • All electronic components must reside within the base and be structurally secured, as well as protected from water
  • The spotlight must be dimensioned for mounting to the deck of a boat (18-65 foot vessels)
  • The external housing will be able to withstand extreme maritime operations

For the overall scope of the project, it is important to understand the inputs from a multifunctional display (MFD) or chart plotter, which provide navigational data, vessel history, absolute GPS position (longitude, latitude, altitude), velocity, and attitude (pitch, roll, yaw). These sources also supply absolute target coordinates, making coordinate system management critical. Both the vessel and target operate in absolute geographic frames whereas the spotlight operates in a local frame, assuming shared latitude and longitude with the vessel.

The four primary coordinate systems (visualized with 3 degrees of freedom).

Final Design and Architectures

The final design shows two independent drive systems (for pan and tilt motions), electronics boxes, 3D printed housings, and key mechanical components. For tilting, a worm gear system is used to transfer torque from the tilt motor to the drive shaft. A direct drive is used with the pan motor to ensure proper rotation of the light.

Isometric view of the full spotlight assembly (left) and a section view of the panning subassembly (right).

The final design was guided by a system architecture encompassing the scope of mechanical and control system design. The components are divided into software and hardware, and the scope is represented by four primary subsystems: the means of pointing, interfaces and wire management, power and motor control, and sensors and data.

Not pictured is the Raspberry Pi 4 which is connected serially to the Arduino MEGA and runs on a separate power source.

Sensors, Data, and User Interfaces

My designated subsystem regards the flow of data: inputs, feedback, and outputs.

The software side of the spotlight’s control system is fully reliant on interprocess communications, the sharing of data between running processes in a computer system. The mechanisms behind interprocess communications are made possible by an operating system, which is why a central computer (Raspberry Pi 4) is needed alongside the microcontroller (Arduino MEGA). There is a plethora of methods to implement interprocess communications, and due to convenience and compatibility, shared memory in the C programming language was chosen as the backbone for the control system development.

Shared memory architecture for spotlight sensors, inputs, and outputs based on shared memory in C.

In the C/C++ programming language, shared memory requires the shmget() and shmat() functions which create shared memory segments and attach data to shared memory segments, respectively. By creating a header file among the source files that contains all of the essential global variables, the code becomes modular, enabling each program to write to and read from shared variables that are predefined. In other words, the vital components of the spotlight control system are decentralized, with special permissions to make updates and receive feedback.

A proof of concept was developed to illustrate the actions that are expected on the software side. In this test, a navigation file continuously prints the vessel’s latitude, longitude, and altitude along a straight-line track where only latitude changes, while the IMU file prints attitude values with a 1/3 chance of random pitch, roll, or yaw drift at each time step. Simultaneously, the target file generates random target coordinates with a 15% chance per update, and the motor control file processes IMU, navigation, and target data to determine pan/tilt corrections. All files terminate once the vessel reaches the destination latitude.

Results from a preliminary interprocess communications proof of concept with labels, color codes, and a video demonstration showing real-time changes in the global variables.

When it comes to the relevant physical electronics, local processing is performed on the Arduino to utilize rapid 10-bit axial position from the absolute encoders on the pan and tilt axes, which influences motor control. The advantage of this scheme is that, by default, the central computer can only have a one-way communication channel with the Arduino which will be used for input commands (connected to a user interface). As a result, the Arduino handles the inner control loop (of position feedback) whereas the Raspberry Pi manages the outer loop (of attitude drift feedback).

Processing scheme for the central computer, microcontroller, and sensors.

The IMU gathers orientation data that is used to form the self-stabilizing mechanism. As a vessel cruises through water at high velocities, there are constant and significant changes in pitch and roll (primarily). The BNO055 sensor mounts to the spotlight as a first-order approximation of the boat’s dynamics. Using Euler orientation angles, drifts in pitch, roll, and yaw are translated into drifts on the pan and tilt axes. Using linear algebra and rotation matrices consisting of Euler angles, the angles for the controllable rotations are computed.

IMU (BNO055) default coordinate system conventions (left) and initial and rotated frames showing the tilt rotation (middle) and pan rotation (right).

These controllable rotations represent drift angles which can be used to correct unstable conditions. The challenge occurs in applying motor control until the drift angles are reduced. Ideally, under unstable conditions, the pan and tilt motors are activated until the drift angles drop below a certain threshold such as $\pm$ 1 degree. The correction angles are a function of the IMU Euler angles ($\alpha$, $\beta$, and $\gamma$):

\[\begin{aligned} \theta_{pan}&=\arccos(\sin\alpha \sin\beta \sin\gamma + \cos\alpha \cos\gamma)\\ \theta_{tilt}&=\arccos(\cos\beta \cos\gamma) \end{aligned}\]

Two user interface concepts were developed as the spotlight was gradually built. The first allows for the user to control spotlight movement from a mobile browser, using Python’s Flask library to host a user interface from the Raspberry Pi. The second and better option was geared more towards customer requirements which advocated for a joystick-style manual control concept. Rather than a joystick, an Arduino script was developed which received keyboard inputs corresponding to directions (left, right, up, down; ‘a’, ‘d’, ‘w’, ‘s’) and kill switches (pan motor off, tilt motor off, both off; ‘m’, ‘n’, ‘o’). Not only does this method reduce latency (as it does not require the internet), but it also grants a hands-on experience for the user to point the light beam at desired targets.

The user interface hosted from a Mac terminal where keyboard keys correspond to spotlight commands (right).

Mechanical and Electrical Assembly

The final prototype demonstrated the desired range of motion for both the pan and tilt axes. Although not shown here, the spotlight is also capable of panning and tilting at the same time, reflecting motor control tasks being commanded in parallel rather than sequentially. Due to the high gear ratio in the worm drive for the tilting mechanical system, the spotlight tilts much slower than it pans. While this can be tuned in the Arduino code, there are hard limitations due to the design and chosen ratio. An on/off switch was also incorporated into the controls, utilizing the toggle switch of the power converter for the light.

Ultimately, there were also limitations in the electrical design. Although the absolute encoders were initialized with correct data readout, it was difficult to implement those signals in the Arduino feedback loop without overloading the control logic. As a quick fix, the specifications of each stepper motor were used in the Arduino code so that the microcontroller can manually compute rotary motion. However, the electronics packaged nicely in the water-resistant boxes and were connected using a series of WAGO connectors around the base.

Electrical assembly and circuit setup, showing the power converters and stepper motor drivers packaged in one of the electronics boxes.

The final assembly significantly reduced the weight and height of the first iteration which was fabricated during the 2023-24 capstone cycle. The tilt drive system also prevented backdrivability of the light, as desired. The final product also improved upon wire management while still preserving essential functions.
